网络数据包传输

前置设定（固定所有地址，全程用这套数字）

  • 🏠 家庭内网网段：192.168.1.0/24，网关 192.168.1.1
  • 📱 手机：内网 IP 192.168.1.100，MAC = M_PHONE: 00:11:22:AA:BB:CC，源端口 50001
  • 🛜 家用路由器（R_HOME）
    • 内网 LAN 口：IP 192.168.1.1，MAC = M_R_LAN: 00:11:22:11:11:11
    • 外网 WAN 口：运营商分配公网 IP 123.45.67.89，MAC = M_R_WAN: 00:11:22:22:22:22
  • 🌐 运营商第一台公共路由器 R1
    • 靠近你家一侧接口 IP：123.45.67.1，MAC = M_R1_IN: 00:11:22:33:33:33
    • 另一侧接口 IP：203.0.113.1，MAC = M_R1_OUT: 00:11:22:33:33:34
  • 🌐 运营商第二台公共路由器 R2
    • 入接口 IP：203.0.113.2，MAC = M_R2_IN: 00:11:22:44:44:44
    • 出接口 IP：180.163.26.1，MAC = M_R2_OUT: 00:11:22:44:44:45
  • 🖥️ 抖音服务器
    • 公网 IP：180.163.26.39，MAC = M_DOUYIN: 00:11:22:55:55:55，服务端口 443（HTTPS）

补充说明

  • 内网交换机：家用路由器内置交换机，二层设备，只转发以太网帧，不改 IP、不改 IP 包头。
  • NAT 表（R_HOME 上）：192.168.1.100:50001 ↔ 123.45.67.89:61001
  • 二层 = 以太网帧（包含源 MAC、目的 MAC + 三层 IP 数据包）；三层 = IP 包头（源 IP、目的 IP）
  • 规则：IP 包头全程源 IP / 目的 IP，只有 R_HOME 会修改（NAT）；每经过一段二层链路，以太网帧的 MAC 全部重写
  • 互联网骨干里的交换机：只是二层转发，只改 MAC，不修改 IP 头

【去程：手机 → 抖音】完整分步

步骤 1：手机生成数据包，封装以太网帧（手机→家用路由器内网口，家庭局域网）

手机要访问抖音 180.163.26.39:443
判断目标 IP 不在192.168.1.0/24网段 → 发给网关192.168.1.1
ARP 已经提前查到网关 IP 对应的 MAC：00:11:22:11:11:11

  • 三层 IP 包头
    • 源 IP：192.168.1.100｜目的 IP：180.163.26.39
    • 源端口：50001｜目的端口：443
  • 二层以太网帧（把 IP 包包在里面）
    • 源 MAC：00:11:22:AA:BB:CC（手机 MAC）
    • 目的 MAC：00:11:22:11:11:11（路由器 LAN 口 MAC）

帧发给路由器内置交换机，交换机查 MAC 地址表，直接转发到 R_HOME 内网口。

步骤 2：家用路由器 R_HOME 收到帧，解二层，执行 NAT，重新封装 WAN 侧二层帧

R_HOME 拆掉二层以太网帧，取出里面 IP 包，读取 IP 头
识别：源内网 IP192.168.1.100:50001，触发源 NAT，在 NAT 会话表写入：192.168.1.100:50001 <---> 123.45.67.89:61001

改写三层 IP 包头（NAT 核心动作！）

  • 源 IP：改成 123.45.67.89（路由器 WAN 公网 IP）｜目的 IP 不变：180.163.26.39
  • 源端口：改成61001｜目的端口依旧443

路由查表：抖音 IP 要转发给下一跳 R1（123.45.67.1），ARP 查到 R1 入接口 MAC
新建 WAN 侧二层以太网帧，包裹修改后的 IP 包

  • 源 MAC：00:11:22:22:22:22（R_HOME WAN 口 MAC）
  • 目的 MAC：00:11:22:33:33:33（R1 入接口 MAC）

数据包发给运营商路由器 R1

步骤 3：公共路由器 R1 收到包，解二层，路由转发，重写二层帧

R1 拆掉二层帧，读取 IP 头：源123.45.67.89，目的180.163.26.39
查路由表，下一跳是 R2（203.0.113.2）

✅ IP 包头【完全不变】，NAT 只在家用路由器做！公网路由器不改 IP

  • 源 IP：123.45.67.89｜目的 IP：180.163.26.39

新建二层以太网帧

  • 源 MAC：00:11:22:33:33:34（R1 出接口 MAC）
  • 目的 MAC：00:11:22:44:44:44（R2 入接口 MAC）

数据包发给 R2

步骤 4：公共路由器 R2 收到包，解二层，路由转发，重写二层帧

R2 拆掉二层帧，读取 IP 头，查路由表，下一跳：抖音服务器180.163.26.39
IP 包头依旧不变：源123.45.67.89，目的180.163.26.39

新建二层以太网帧

  • 源 MAC：00:11:22:44:44:45（R2 出接口 MAC）
  • 目的 MAC：00:11:22:55:55:55（抖音服务器 MAC）

数据包送达抖音服务器。抖音服务器拆包，读取请求内容。

【回程：抖音 → 手机】完整分步

核心前提：抖音收到请求后，构造响应包。抖音只看到公网地址 123.45.67.89:61001，不知道手机内网地址。回程同样：公网路由器不改 IP，只换 MAC；只有家用路由器 R_HOME 做 NAT 反向转换

步骤 5：抖音服务器封装响应包，发给 R2

抖音构建响应 IP 包，源目 IP、端口和去程反过来

  • 三层 IP 包头
    • 源 IP：180.163.26.39｜目的 IP：123.45.67.89
    • 源端口：443｜目的端口：61001

查路由表，下一跳是 R2（180.163.26.1），ARP 获取 R2 出接口 MAC
新建二层以太网帧

  • 源 MAC：00:11:22:55:55:55（抖音服务器 MAC）
  • 目的 MAC：00:11:22:44:44:45（R2 出接口 MAC）

数据包发给 R2

步骤 6：公共路由器 R2 收到响应包，解二层，路由转发，重写二层帧

R2 拆掉二层帧，读取 IP 头：源180.163.26.39，目的123.45.67.89
查路由表，下一跳 R1（203.0.113.1）
✅ IP 包头保持原样，公网路由器不修改 IP

  • 三层 IP 包头
    • 源 IP：180.163.26.39｜目的 IP：123.45.67.89
    • 源端口：443｜目的端口：61001

新建二层以太网帧

  • 源 MAC：00:11:22:44:44:44（R2 入接口 MAC）
  • 目的 MAC：00:11:22:33:33:34（R1 出接口 MAC）

数据包发给 R1

步骤 7：公共路由器 R1 收到响应包，解二层，路由转发，重写二层帧

R1 拆掉二层帧，读取 IP 头：源180.163.26.39，目的123.45.67.89
查路由表，下一跳 R_HOME 的 WAN 口（123.45.67.89）
✅ IP 包头保持原样

  • 三层 IP 包头
    • 源 IP：180.163.26.39｜目的 IP：123.45.67.89
    • 源端口：443｜目的端口：61001

新建二层以太网帧

  • 源 MAC：00:11:22:33:33:33（R1 入接口 MAC）
  • 目的 MAC：00:11:22:22:22:22（R_HOME WAN 口 MAC）

数据包发给家用路由器 R_HOME

步骤 8：家用路由器 R_HOME 收到响应包，解二层，反向 NAT 转换，内网转发

R_HOME 拆掉 WAN 侧二层帧，取出 IP 包
读取目的 IP 和端口：123.45.67.89:61001
查询 NAT 会话表：192.168.1.100:50001 ↔ 123.45.67.89:61001
👉 反向 NAT：改写三层 IP 包头

  • 源 IP：180.163.26.39（不变）｜目的 IP：修改为 192.168.1.100
  • 源端口：443（不变）｜目的端口：修改为 50001

现在 IP 包目标变成手机内网地址。ARP 已经查到手机 MAC。
新建内网 LAN 侧二层以太网帧

  • 源 MAC：00:11:22:11:11:11（R_HOME LAN 口 MAC）
  • 目的 MAC：00:11:22:AA:BB:CC（手机 MAC）

帧交给路由器内置交换机，交换机查 MAC 地址表，转发到手机。

步骤 9：手机收到以太网帧

手机拆掉二层帧，取出 IP 包，交给上层应用，收到抖音返回的数据。

总结

  1. IP 包头：跨互联网全程不变，只在家路由器 NAT 处修改（去程改源 IP / 端口，回程改目的 IP / 端口）
  2. 二层 MAC 地址：每一跳链路，全部换掉，MAC 只在当前这一段局域网有效，不能跨互联网
